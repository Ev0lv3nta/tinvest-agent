# tinvest-agent

Стенд для наблюдения за автономным торговым агентом в песочнице T-Invest API.

Агент работает сам: просыпается по собственному расписанию, изучает рынок,
принимает решения и торгует. Задача стенда — не заработать, а увидеть, как он
это делает, и получить журнал, по которому решения можно разобрать постфактум.

Деньги в песочнице виртуальные. Боевой контур не подключён и подключаться не будет.

## Устройство

```
supervisor  ──stdio──>  codex app-server  ──MCP──>  gateway
     │                                                 │
     ├── наблюдатели за ценой и страницами             ├── T-Invest sandbox (REST)
     ├── таймеры, дедмен, healthcheck                  ├── ограничители риска
     ├── Telegram в обе стороны                        ├── веб-поиск
     └── журнал в SQLite                               └── журнал и данные на диск
```

`supervisor` держит одну длинную сессию агента и будит её по событиям:
сработало условие наблюдения, пришло сообщение оператора, наступило время
события. Сам агент внутри сессии не перезапускается, поэтому контекст между
пробуждениями не теряется.

За рынком следит код, а не модель: условия регистрируются инструментом `watch`
и проверяются фоновым потоком одним батч-запросом раз в полминуты. Пока условие
не выполнено, это не стоит ни токена.

Объёмные данные не проходят через контекст: свечи пишутся в CSV, наружу идёт
сводка и путь к файлу.

`gateway` — MCP-сервер с торговыми инструментами и ограничителями. Живёт
отдельным процессом вне рабочей директории агента. Ограничители в нём агент не
правит; журнал технически доступен ему на запись, потому что процессы работают
от одного пользователя — поэтому торговля мимо шлюза не запрещается, а
обнаруживается сверкой операций.

## Ограничения

Заданы в коде, а не в инструкциях:

- стартовый капитал 100 000 ₽, пополнений по ходу нет;
- плечо запрещено — заявка на сумму больше свободных денег отклоняется;
- шорт запрещён — продать больше, чем есть в портфеле, нельзя;
- риск на сделку не больше 1% капитала, размер считается от стопа;
- соотношение прибыль/риск не меньше 2, цель не меньше десяти круговых комиссий,
  стоп не ближе 1,5 ATR(15м);
- не больше 2 позиций, 4 входов в день, дневной стоп −3%;
- пауза 45 минут после убыточного выхода из бумаги;
- не более 30 заявок в час.

Остановка прогона и дневной стоп закрывают вход, но не выход: избавиться от
риска можно всегда.

Песочница не считает маржинальные показатели и допускает отрицательный баланс,
поэтому проверки делаются на нашей стороне до отправки заявки.

## Тесты

```
python3 -m unittest discover -t . -s tests
```

Покрыто то, что должно ломаться громко: барьеры входа, семантика остановки,
идемпотентность заявки, доставка событий без потерь, сопоставление операций,
авторизация панели.

## Требования

Python 3.11+, ничего сверх стандартной библиотеки. Codex CLI с
`codex-code-mode-host` — без него MCP-инструменты не доедут до модели.

Сертификат `deploy/RussianTrustedRootCA.pem` нужен для TLS до API Т-Банка:
цепочка подписана Минцифры, в системных хранилищах её нет. Передаётся клиенту
явно, системное хранилище не трогается.
