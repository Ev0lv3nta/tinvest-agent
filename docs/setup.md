# Запуск стенда

Для знакомства с проектом достаточно двух демо из README. Этот документ —
про полный стенд с внешними сервисами. Скрипты ниже предполагают отдельную
Linux-машину с systemd и доступом root; локальную macOS они не настраивают.

## Что потребуется

- Python 3.11+, Git, OpenSSH; для скрипта обновления — `tar` и `sha256sum`.
- Токен **песочницы** T-Invest и ID заранее созданного sandbox-счёта.
- Codex CLI с поддержкой используемого здесь app-server и MCP. Скрипт установки
  не ставит CLI. Супервизор по умолчанию ищет `/usr/local/bin/codex`; другой
  путь задаётся через `CODEX_BIN` в systemd override.
- Шлюз модели, который обслуживает `/v1/models`, `/v1/responses` и нужные
  инструменты. В исходном стенде используется OmniRoute. Имя модели и endpoint
  в `deploy/codex-config.toml` — пример конфигурации этого стенда.
- Для Telegram — токен собственного бота и ID оператора. Для входа в панель
  через браузер достаточно `WEBAPP_KEY`.

Интеграция app-server зависит от его версии. Ожидаемые запросы и события
зафиксированы в `supervisor/appserver.py` и тестах супервизора. Совместимость
с установленной сборкой нужно проверить перед длительным прогоном; CI
проверяет протокол на подставном процессе, а не на внешней модели.

## Первая установка

На сервере, от root:

```bash
git clone https://github.com/Ev0lv3nta/tinvest-agent.git /opt/tinvest-agent
cd /opt/tinvest-agent
bash deploy/install.sh
install -o agent -g agent -m 600 .env.example /home/agent/.agent.env
```

Установка создаёт пользователя `agent`, каталоги состояния и systemd units.
Она включает службы для запуска при загрузке ОС и сразу запускает таймер
резервного копирования. Агент и панель запускаются отдельно после настройки.
Повторная установка сохраняет существующую конфигурацию Codex и заметки агента.

Заполните `/home/agent/.agent.env`:

| Переменная | Для чего |
| --- | --- |
| `TINVEST_TOKEN` | Доступ к песочнице брокера |
| `TINVEST_ACCOUNT_ID` | Счёт в песочнице |
| `OMNIROUTE_BASE_URL` | URL шлюза с `/v1` на конце |
| `OMNIROUTE_API_KEY` | Ключ шлюза модели |
| `OMNIROUTE_MGMT_KEY` | Необязательно: чтение квот OmniRoute; без него квоты в панели недоступны |
| `WEBAPP_KEY` | Случайный ключ входа в панель |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Необязательно: бот и разрешённый оператор |

Сгенерировать ключ панели:

```bash
python3 -c 'import secrets; print(secrets.token_urlsafe(32))'
```

В `/home/agent/.codex/config.toml` задайте доступную модель и адрес провайдера.
Адрес должен совпадать с `OMNIROUTE_BASE_URL`. Шаблон использует локальный
порт 20128; без работающего шлюза или туннеля там ничего не будет.

Python-процессы читают секреты из окружения, затем из `/home/agent/.agent.env`
и `.env` в корне проекта. Пути `AGENT_DB`, `AGENT_DATA_DIR`, `AGENT_WORKDIR`,
`RESEARCH_DB` задаются **окружением**, а не файлом секретов. В комплектных
systemd units они уже направлены в `/home/agent/`.

## Если нужен SSH-туннель

При прямом доступе к шлюзу этот шаг не нужен. Служба туннеля пропускает запуск,
если `/etc/tinvest-agent/tunnel.env` отсутствует.

```bash
install -d -m 700 /etc/tinvest-agent
install -m 600 deploy/tunnel.env.example /etc/tinvest-agent/tunnel.env
```

Задайте в файле SSH-пользователя, хост, путь ключа и перенаправление порта.
Добавьте проверенный ключ хоста в `/root/.ssh/known_hosts` и проверьте вход
выбранным ключом вручную. Служба работает без запроса пароля и не принимает
неизвестный ключ хоста автоматически.

```bash
systemctl start omniroute-tunnel
systemctl status omniroute-tunnel
```

## Панель и запуск агента

```bash
systemctl start tinvest-panel
```

Панель по умолчанию слушает `127.0.0.1:8080`. Для просмотра с рабочей машины:

```bash
ssh -N -L 8080:127.0.0.1:8080 user@your-server
```

Откройте `http://127.0.0.1:8080/?k=ВАШ_КЛЮЧ`. Страница убирает ключ из адреса
и использует его в заголовке последующих запросов. Не публикуйте такую ссылку.
До первого запуска супервизора база может отсутствовать, и панель ещё не
сможет показать состояние. Для внешнего доступа нужен reverse proxy с HTTPS.

Когда конфигурация готова:

```bash
systemctl start tinvest-agent
journalctl -u tinvest-agent -f
```

**Эта команда запускает автономного агента:** он сможет расходовать квоту модели
и отправлять заявки в sandbox-счёт. Наблюдайте первый запуск: доступность модели,
подключение MCP, чтение счёта, запись событий и восстановление после остановки.
Успешный импорт Python-модулей сам по себе этого не проверяет.

Остановить супервизор: `systemctl stop tinvest-agent`. Вместе с ним остановится
и поток исполнения стопов; это не способ закрыть открытые позиции.

## Обновление

С рабочей машины, из корня репозитория:

```bash
bash deploy/push.sh root@your-server
```

Архив собирается из **HEAD**, без незакоммиченных файлов и `.env`. На сервере
проверяются контрольная сумма, импорт и тесты; затем заменяется каталог кода.
Если агент был остановлен, обновление оставляет его остановленным. Проверка
старта службы после замены короткая и не является сквозным тестом брокера.

`push.sh` обновляет код, но не переустанавливает systemd units. При изменении
units отдельно выполните `bash deploy/install.sh` и перезапустите нужные службы
в выбранное окно обслуживания. Если переходите со старого unit с зашитым
SSH-адресом, сначала создайте `tunnel.env`, иначе туннель не поднимется.

Резервные копии SQLite создаются раз в час от root в `/var/backups/tinvest-agent`.
Инструмент `deploy/reset_session.py` сбрасывает сессию и заметки; для обычного
обновления он не нужен.
